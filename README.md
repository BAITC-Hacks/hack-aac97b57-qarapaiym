# Аким на 5 часов

AI-симулятор для городского управленца, аналитика и жюри HackAlem. Пользователь распределяет **100 условных единиц** между **ровно пятью мероприятиями**, назначает районы и сравнивает последствия за 8 кварталов. Данные и формула взяты из текста задания, предоставленного командой: [транскрипция кейса](docs/OFFICIAL_CASE.md).

**Score рассчитывает код. AI объясняет готовый результат, сильные стороны, риски, последствия и компромиссы.** Это учебная модель, не прогноз и не официальная статистика Астаны.

## Установка

Нужны Node.js 24 LTS (или ≥22.12) и npm. Из корня репозитория:

```sh
npm ci
cp .env.example .env.local
npm run dev
```

В PowerShell используйте `Copy-Item .env.example .env.local`. Откройте http://localhost:3000. Без ключа работают расчёты и сравнение, AI показывает сообщение о настройке.

```sh
npm test
npm run typecheck
npm run build   
npm start
```

Перед production-запуском остановите свой dev-процесс. Если Turbopack в ограниченной среде падает при запуске CSS-процесса с `EPERM`, используйте `npm run build -- --webpack`. Данные включены в Git; базы данных и миграций нет.

## AI-провайдер

В `.env.local` задайте `OPENAI_API_KEY`. Не коммитьте ключ и не добавляйте `NEXT_PUBLIC_`. `OPENAI_MODEL` по умолчанию — `gpt-5.6-luna`; модель должна поддерживать Structured Outputs в Responses API. После изменения окружения перезапустите свой сервер.

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-5.6-luna
```

Нужны доступ сервера к `api.openai.com` и действующий API-аккаунт. Сервер повторно рассчитывает сценарий, отклоняет подменённые результаты и отправляет провайдеру выбранные меры, районы, стоимость, лаги, реализованные эффекты, синергии, показатели до/после и компоненты Score. `store:false`, тайм-аут 60 секунд. Ошибка AI не отменяет расчёт; доступен повтор запроса. Подставных production-объяснений нет.

## Правила выбора

- Ровно 5 разных мер из официального каталога M1–M14.
- Не более 2 мер в одном направлении, поэтому охвачены минимум 3 направления. **По одной в каждой из пяти сфер не требуется**: подробные правила и пример задания допускают две социальные меры.
- Районная мера требует район. Городская действует во всех пяти районах и не принимает район.
- Расход не выше 100; остаток не даёт бонуса.
- M1/M3 несовместимы в любых районах. M4/M7 и M5/M13 несовместимы в одном районе.
- При нарушении правил результат сценария отсутствует (`projected:null`, `delta:null`), валидатор возвращает причины. Базовое состояние доступно отдельно.

## Формула AQoL

1. В каждом районе десять показателей: T1/T2, E1/E2, S1/S2, B1/B2, C1/C2. Все направлены одинаково: больше — лучше.
2. Реализованный эффект меры = полный эффект × `(8 − лаг) / 8`.
3. Фиксированные синергии: M1+M2 → T1+2 в районе M1; M10+M12 → B1+2 в районе M10; M5+M6 → E2+2 в районе M5. Они не масштабируются лагом.
4. Все эффекты суммируются, затем значения ограничиваются 0–100.
5. Районный балл `D = Σ(w × показатель)`. Веса: T1 0,10; T2 0,10; E1 0,09; E2 0,11; S1 0,11; S2 0,11; B1 0,09; B2 0,09; C1 0,10; C2 0,10.
6. `D_avg = Σ(доля населения × D)`.
7. **Score = 0,7 × D_avg + 0,3 × min(D) − N_crit**, где N_crit — число пар «район × показатель» строго ниже 40.

Вычисления используют неокруглённые значения. Отображение Score и прироста — два знака, округляются независимо; разность отображаемых Score иногда отличается на 0,01 от отображаемого прироста. Исходный Score: **52,55768 → 52,56**. Вспомогательные баллы пяти направлений — нормированные взвешенные средние; они не заменяют официальную формулу.

## Воспроизводимый показ

1. Начальное состояние: **100 у. е.**, AQoL **52,56**, два критических показателя Нуры.
2. Сценарий A из задания: **M7 Нура, M8 Нура, M10 Нура, M12 весь город, M5 Сарыарка**. Добавляйте меры через вкладки, предварительно выбирая район.
3. Расход **95**, остаток **5**. Нажмите «Рассчитать сценарий». Score **56,54**, прирост **+3,99** от неокруглённой базы. Критических показателей **0**; срабатывает M10+M12. Числа появляются до AI-текста.
4. Сохраните A. Измените только район **M7 на Есиль**, пересчитайте B. Расход тот же, Score **55,30**, критических показателей **1**: S1 Нуры остаётся 38. AI должен объяснить этот компромисс.
5. Точный бюджет: M1 Нура + M2 город + M4 Сарыарка + M5 Сарыарка + M8 Нура = **100**, Score **55,34**.
6. Перерасход: M1 Нура + M2 город + M5 Сарыарка + M6 город + M14 город = **101**. Последняя мера заблокирована; движок/API также отвергают набор.
7. «Сбросить решения» возвращает 0/5 и 100. Сохранённый A удаляется отдельной кнопкой или перезагрузкой.

[Сценарий выступления на 60–90 секунд](docs/JUDGE_DEMO_RU.md). [Проверки и ограничения](docs/VERIFICATION.md).

## Технологии и архитектура

TypeScript, React 19, Next.js 16 (App Router), Tailwind CSS 4, Lucide, Vitest, OpenAI Responses API. Версии зависимостей зафиксированы в lock-файле.

| Компонент | Роль |
|---|---|
| `data/city-demo.json`, `src/lib/data` | Официальный синтетический набор и структурный валидатор |
| `src/types/city.ts` | Десять показателей, веса и контракт |
| `src/lib/simulation` | Все ограничения, лаги, синергии, Score и вклад мер |
| `src/app/page.tsx` | Выбор пяти мер/районов, результаты, A/B, сброс |
| `src/app/api/analyze` | Повторный расчёт и проверка канонического результата |
| `src/lib/ai` | Реальный провайдер, схема ответа, ошибки |

Браузер и сервер используют один движок. При изменении решений старые результаты и AI-текст сбрасываются, незавершённый запрос отменяется. Сравнение A/B хранится только до перезагрузки. В приложении нет автономного agentic-планировщика: AI интерпретирует результат одного сценария.

## Данные и честные ограничения

Пять условных районов, доли населения, десять показателей, 14 мероприятий, цены и эффекты перенесены из предоставленного текста кейса. Они **синтетические**, не отражают реальное население, закупки или измерения Астаны. Внутренняя прежняя модель с бюджетом 1 000 и пятью показателями заменена после получения полного задания.

Модель имеет заданный горизонт и лаги, но не рассчитывает поквартальную траекторию, инфляцию, эксплуатационные расходы или неопределённость причинных эффектов. Одинаковый суммарный Score возможен для разных планов — показатели районов при этом могут различаться. AI может ошибаться: проверка структурированного evidence не доказывает истинность каждого предложения. Числа движка — источник истины.

Нет сравнения разных команд, публичного хранения сценариев, случайных событий или генерации презентаций. Эти возможности опциональны в кейсе. Публичный платный API требует отдельной защиты от злоупотреблений; deployment не выполнен.
